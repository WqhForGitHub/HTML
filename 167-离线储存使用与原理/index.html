HTML5 离线储存的使用与原理

面试题 16 · Application Cache

概述

HTML5 离线储存早期方案是 Application Cache (AppCache)，通过 manifest 文件声明离线资源，由浏览器缓存并在离线时使用。

⚠ AppCache 已被 W3C 标注为废弃，现代方案用 Service Worker + Cache Storage（PWA）。两者原理类似，这里以 AppCache 为代表。

使用步骤

① 编写 manifest 文件：

CACHE MANIFEST # v1.0 注释变更版本号触发更新 CACHE: # 需要离线缓存的资源 /index.html /app.js /style.css NETWORK: # 必须在线访问的资源，离线不缓存 /login FALLBACK: # 离线时后备方案 /api/ /offline.html

② HTML 引入 manifest：

<html lang="zh-CN" manifest="/app.manifest"> <!-- manifest MIME 必须是 text/cache-manifest -->

工作原理

1浏览器首次加载页面，解析到 manifest 属性
2下载 manifest 文件，按 CACHE 列表下载所有资源
3浏览器把资源存入离线缓存（独立于 HTTP 缓存）
4触发 window.applicationCache 的 cached 事件
5之后访问——即使没有网络——浏览器也直接走离线缓存
6再次访问时浏览器先检查 manifest 是否变更，变了才下载新版
7新版下载完成触发 updateready，调用 swapCache 切换

核心特点

1. 以 manifest 为索引：只有 manifest 变更才更新缓存，资源本身变化不更新。

2. 三段结构：CACHE / NETWORK / FALLBACK 分明。

3. 自动浏览：在线时也优先用缓存（除非 NETWORK 声明）。

4. 更新不可控：用户必须刷新，且首次访问永远是旧缓存。

替代方案：Service Worker

navigator.serviceWorker.register('/sw.js') .then(reg => console.log('注册 OK')) // sw.js: install 缓存 → fetch 拦截 self.addEventListener('install', e => { e.waitUntil(caches.open('v1') .then(c => c.addAll(['/','/index.html','/app.js']))) }) self.addEventListener('fetch', e => { e.respondWith(caches.match(e.request).then(r => r || fetch(e.request))) })
💡 离线储存关键 = "声明清单文件 → 浏览器缓存 → 离线时命中缓存 → 通过版本号触发更新"。现代应用请用 Service Worker（PWA），更灵活可控。
